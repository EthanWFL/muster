# Muster 1.1.1

修复正式发布缺少更新公钥和 DMG 签名，导致“下载并安装”不可用的问题，并重写项目首页。

## 自动更新修复

- 正式构建默认内置固定的 Ed25519 更新公钥，签名私钥长期保存在仓库外。
- Release 同时提供 DMG、匹配的 `.dmg.sig` 和 SHA-256。缺少私钥、密钥不匹配或产物验证失败时，正式发布流程会停止。
- 安装器继续在挂载前验证发布签名，并核对应用标识、版本、架构和目标路径；同时检查新包保留当前信任公钥，防止更新后再次失去更新能力。
- 替换前复核当前应用身份，退出旧进程后从同一路径重启；不会绕过权限检查或后台静默安装。
- 设置页区分“旧构建需要一次手动迁移”与“远端缺少可验证的安装包／签名”。

## README 与文档

首页改为项目介绍、功能概览、安装与快速开始、常用操作、开发入口及许可证声明。详细功能、文件路径和边界行为保留在使用说明；开发与签名发布流程分别成文，历史 Release 文档保留。

项目整体许可证仍未声明，第三方 Yams／LibYAML 许可单独保留。

## 验证

本地通过 248 项单元与回归测试、缺少／不匹配／权限不安全的发布密钥拒绝检查，以及隔离应用的 HTTPS 下载、签名与篡改拒绝、目标路径检查、替换和实际重启验证。发布前对最终 DMG 的签名、公钥、应用版本及 SHA-256 做一致性检查；CI 记录见 Release。

## 旧版本迁移

**1.0.0、1.1.0 等没有内置更新公钥的旧版本，必须手动安装一次 1.1.1。** 仅补充远端签名无法建立旧应用缺少的信任锚点。隔离测试使用带公钥的旧版副本模拟更新，不能据此认为已发布的无公钥旧版可以直接自动升级。

完成迁移后，发现后续签名版本时可在“设置 → 关于”点击“下载并安装”，由应用完成下载、校验、替换和重启。更新前请保存未落盘的编辑。

安装包仍支持 macOS 14+、Apple Silicon（arm64），使用 ad-hoc 代码签名，尚未经过 Apple 公证。首次手动安装可能需要在系统设置中允许打开；应用需位于可写安装目录。更新签名不替代 Apple 公证。
