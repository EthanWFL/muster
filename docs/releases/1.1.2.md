# Muster 1.1.2

重做技能模块的主要交互：解决 Agent 目录已有同名技能时无法部署的死锁，补齐删除、重命名、附属文件编辑、批量部署，并让耗时操作可见、可取消。

## 技能模块

- **接管已有技能目录。** 目标位置存在同名技能时，预览会把它标为可接管，默认仍不写入；用户逐个允许（或一次性「全部备份并替换」）后才执行。原目录先移入 `library/backups/<事务 ID>/`，不会被直接删除；停用该部署时原目录还原回 Agent 目录。不含 `SKILL.md` 的目录永远不会被接管。这一改动解开了此前“必须先手动删掉 Agent 目录里的技能才能部署”的死锁。
- **删除与重命名。** 版本菜单新增「重命名技能…」和「从技能库删除」。重命名只改写 frontmatter 的 `name`，其余字段和所有文件原样保留；删除会清理该技能的版本目录、草稿和失效的部署日志。两者都要求该技能当前没有部署，避免 Agent 目录留下指向旧名称的空链接。
- **附属文件可编辑。** 编辑器除 `SKILL.md` 外，还能直接修改、新增、移除 `references/`、`scripts/` 等文本文件，草稿会一并保存。发布前校验相对路径，`..`、绝对路径和空段都会被拒绝；二进制或过大文件仍只列出、需在访达中编辑。
- **批量部署。** 列表新增勾选框，勾选多个技能后可一次预览、统一启用或停用并切换链接／副本，作为单个事务执行。勾选只改变批量集合，不会把编辑器从正在阅读的技能上移走。存在未应用的变更时，列表底部常驻入口，行内也会标注「需要更新」。
- **来源自指时不再误报“已是最新”。** 从 Agent 目录导入的技能，一旦 Muster 部署回那个目录，该目录就不再能作为更新来源。此情况下界面直接说明原因并禁用检查，而不是重新扫描技能库自身、永远返回同一个结果。
- **空部署区说明具体原因。** 没有任何 Agent 既已安装又已纳入管理时，会写明支持哪几个 Agent，并指出去「设置 → Agent 管理」启用哪一个。
- **耗时操作可见、可取消。** Git 克隆、扫描、导入和部署都会在底部显示当前步骤和「取消」按钮，期间不再静默丢弃点击。

## 一并修复的既有缺陷

- 发布新版本时，若覆盖了某个已有附属文件，同一相对路径会被写入两次，导致修订摘要无法与目录内容一致。此问题会影响带附属文件技能的更新。
- 接管备份的清理逻辑按绝对路径前缀匹配，在 `/var` 指向 `/private/var` 的 macOS 上会立刻删掉刚写好的备份。现在按事务 ID 匹配，且备份的生命周期与对应部署绑定，不会因为部署日志滚动到 20 条以外而让用户的原目录被永久删除。

## 验证

`swift build -c release` 通过，264 项单元与回归测试全部通过（较 1.1.1 新增 16 项，覆盖接管与还原、备份跨日志滚动存活、删除与重命名的部署约束、批量部署、草稿路径校验、附属文件发布，以及应用层模型的批量选择与待应用状态）。发布前对最终 DMG 的签名、公钥、应用版本及 SHA-256 做一致性检查。

## 安装

从 1.1.1 起正式构建内置固定的更新公钥，可在「设置 → 关于」点击「下载并安装」完成更新。**1.0.0、1.1.0 等没有内置公钥的旧版本仍需手动安装一次。** 安装包仍支持 macOS 14+、Apple Silicon（arm64），使用 ad-hoc 代码签名，尚未经过 Apple 公证。
