# Muster 使用说明

日常入口、安装与更新见[项目首页](../README.md)。本文保留详细功能、路径和行为说明。

## 功能

**项目工作台（Projects）**
独立管理窗口新增「项目」入口，以项目列表和详情两栏展示。点击「＋」选择本地文件夹即可添加，没有 Agent 会话的项目也会保留；已有会话会按完整工作目录自动发现项目，同名不同路径分别展示。手动收录的目录会汇总子目录会话，另外添加的子项目优先归入自身。路径按词法规范化，不会自动合并符号链接或不同 worktree。

项目详情集中显示最近／全部会话、待处理标记、备注摘要和已关联的产物目录。点击会话标题或「查看备注」进入会话编辑器。和会话页一样，行右侧只在识别到运行中的来源客户端时显示其图标；点击切回该应用，不启动终端或复制命令。分支仅在当前会话扫描有信息时展示。

项目支持搜索、固定、修改显示名称和移出列表。移出只隐藏项目，刷新后不会重新出现，项目目录和会话均保留；再次选择同一目录可恢复显示。名称、固定状态和隐藏记录保存于 `~/Library/Application Support/Muster/projects.json`，会话标注继续使用原会话库。快速面板展示精简项目列表，选择项目后打开管理窗口。

**桌面项目轮盘**
在管理窗口的项目列表勾选常用项目，然后点击窗口底部「退出」旁的轮盘图标。灰色空心表示已关闭，强调色实心表示已开启。鼠标移到桌面熊猫上会展开项目扇区，左键点项目可在 VS Code 打开该目录，已打开时会切回对应窗口。每页显示最多六个项目，多页时点击中心熊猫翻页。

按住中心熊猫拖动可调整桌面位置。贴近屏幕边缘时，轮盘会向可用区域内展开，收起后回到拖放位置。再次点击同一图标即可关闭桌面轮盘，下次启动轮盘会沿用上次的位置。

**会话（Sessions）**
扫描本机进程，识别 Claude Code / Codex / Pi / DeepSeek Harness / Gemini CLI / Cursor / OpenCode 七个 CLI，按 Agent 分组。每 15 秒自动刷新，也可手动重扫。Claude Code、Codex、Pi 会结合本地 transcript 元数据显示「最近活跃」或「暂无新活动」；只有进程信息时显示「活动未知」，这些状态都不代表任务完成。

会话行最右侧显示当前运行客户端的小图标，例如 Warp、Terminal、iTerm、VS Code、Cursor、Codex 或 ChatGPT 桌面端，悬浮显示名称。默认切回已运行的客户端。Warp 稳定版的本地 zsh 面板完成登记后，悬浮提示会变成「回到 Warp 会话」，点击可选中该面板。来源沿当前进程的父进程链识别，图标直接读取本机应用包；不把 Agent 可执行文件所在的资源目录当作启动客户端。会话与进程无法唯一关联、父进程不可读、经过 tmux/screen/SSH，或进程已退出时不强行标注。来源不保存到历史记录，标题和目录旁不再重复显示。会话页已移除旧终端定位、终端恢复和复制恢复命令的按钮与菜单入口。

**在 Warp 中启用精确定位**

将下面一行加入 `~/.zshrc`，新开的 Warp 面板会自动登记。已有面板可在提示符执行同一行。若应用放在其他位置，将 `/Applications/Muster.app` 改为实际路径。

```zsh
[[ $TERM_PROGRAM == WarpTerminal && -r '/Applications/Muster.app/Contents/Resources/Muster_Muster.bundle/muster-warp.zsh' ]] && source '/Applications/Muster.app/Contents/Resources/Muster_Muster.bundle/muster-warp.zsh'
```

登记脚本把 Warp 提供的面板标识写入 `~/Library/Caches/Muster/warp-panes/`，文件按 shell PID 和启动时间区分，正常退出时删除。Muster 根据会话的进程祖先匹配面板，同一目录中的多个面板可以分别定位。缺少登记时，Logo 仍可切回 Warp。

菜单栏图标旁只显示运行会话总数，例如 `5`。只统计当前管理范围内可识别且仍关联存活进程的会话，不计历史记录，也不展示活跃比例。悬浮可查看统计说明，随每 15 秒扫描及管理范围变化自动更新。

进程与 transcript 只在候选唯一、时间吻合时关联；同目录多个候选会保留独立条目，不猜测对应关系。悬停状态可查看是否已关联存活进程。行内显示项目路径、git 分支和距最近活动的时间（仅进程条目显示启动时长），右侧来源 Logo 可激活当前客户端。

已关联存活进程的会话，在观察到活动后持续 60 秒没有新活动时提醒，同一轮暂停只提醒一次。设置飞书自定义机器人 webhook 后也可同步推送。

支持搜索项目路径、Agent、分支、会话 ID 和 PID，空格分隔的词需同时匹配；可按活动状态筛选，或按 Agent／完整工作目录分组。同名但不同路径的项目分别展示，分组方式会记住。没有匹配结果时可一键重置筛选。

独立管理窗口的「会话」页提供本地会话库：顶部切换「最近」（24 小时内或仍关联存活进程）和「历史」，按全部、待处理、未分类或自建分类筛选。选中会话后可修改标题、标记待处理、填写备注、关联产物目录，按 `⌘S` 保存。搜索同时覆盖标题、项目路径、Agent、备注、分类和产物路径。菜单栏面板显示自定义标题、待处理总数和会话库入口。

每次启动后首次打开会话库，导入最近 30 天的 Claude Code、Codex、Pi 本地记录；右上角刷新菜单可以导入全部历史，也可取消正在进行的扫描。导入只保存会话元数据，不保存对话正文。没有 transcript 的临时进程仍可查看和打开来源客户端，暂不支持历史整理。历史条目仅在本次扫描关联到存活进程时提供来源跳转。

标题、分类、备注、待处理标记和产物目录保存在 `~/Library/Application Support/Muster/session-library.json`，退出 Agent 或重启 Muster 后仍保留。整理操作支持撤销最近 50 次更改，导入不会覆盖标注或占用撤销记录。删除分类会将其中会话改为未分类，保留会话和原文件。本阶段标注仅在 Muster 内生效，不同步修改 Claude / Codex 的标题或侧边栏。

会话编辑区底部统一显示未保存、保存中或已保存状态；再次编辑或切换会话时，不会保留上一轮保存成功提示。会话库与设置、规则页共用按钮、分段选择和下拉样式，按钮字号与输入框高度随舒适布局调整。

`⌘F` 定位搜索；菜单栏快速面板中，搜索框内按 Enter 或 ↓ 进入结果列表，上下键选择会话，Enter 激活已识别的客户端，`⌘R` 刷新。`⌘1`–`⌘4` 按当前标签顺序切页，`⌘,` 打开设置，管理窗口中 `⌘W` 关闭窗口。

**清理（Cleanup）**
三类残留：监听端口、孤儿进程、已合并但没删的 worktree。先给计划（哪条命令、影响什么对象），确认后才执行——展示和执行用的是同一份数据。归属靠启发式打分（命令行、父子进程树、cwd），拿不准的标「不确定」且默认不勾；删目录这类不可逆操作要再点一次确认。只有页面可见时才做完整扫描，后台每 10 秒采一次进程快照（孤儿判定需要历史），最后一个会话退出后仍继续跟踪已登记的子进程，直到这些进程退出。扫描不会并发叠加。

执行后区分「已发送 SIGTERM」「等待退出」和「进程已退出」，面板收起后仍跟踪退出结果。10 秒后仍未退出的进程会提供「强制结束」入口，需要单独确认，且执行前再次核对进程身份。

**统一 Agent 管理范围**
「设置 → Agent 管理」统一选择 Muster 需要处理的 Agent。默认跟随本机安装检测；手动修改任一开关后保存为自定义清单，新安装的 Agent 不会自动加入。支持「全选已检测到」「清空选择」和恢复「跟随安装检测」，清单重启后保留。

会话列表、历史导入、待处理计数和项目内的相关会话按清单筛选；规则、模型配置和技能部署的写入目标仅包含已勾选且检测到安装的 Agent；配置列表保留全部已勾选项，缺少安装或文件时给出说明。取消勾选只改变 Muster 的展示与后续操作范围，保留文件、历史标注、草稿和已有技能部署；重新勾选后可继续使用。未检测到但已选择的 Agent 仍可查看其保存的会话历史。清空清单会显示设置入口，不会偷偷回退成全选。

活动暂停通知和环境诊断也遵循清单。清理只给所选 Agent 生成操作计划，但保留其他运行中 Agent 的只读进程归属信息，防止误认进程；切换范围会作废旧清理选择。已经发起的清理继续追踪结果，不会因为隐藏条目而丢掉执行状态。

**Agent 工作区**
规则、技能和配置统一放在「Agent」页内。管理窗口左侧的 Agent 可展开为「规则、技能、配置」二级菜单，当前子页单独高亮，记住上次选择。大小窗口均不再提供 Agent 筛选下拉，管理范围统一在设置中选择；规则和技能始终展示当前管理范围，旧筛选值不再隐藏内容。配置页列出已勾选的 Agent，点击具体条目进入编辑，点「全部配置」返回列表。勾选但未检测到安装、没有配置文件或暂不支持共享规则的 Agent 会显示对应说明；实际写入和技能部署仍限于已检测到安装的目标。安装检测检查 PATH、常见命令目录以及应用目录中的有效应用包，不将残留配置或技能文件夹视为安装证据，也不运行 Agent 程序。可在「设置 → Agent 管理」重新检测；非标准安装目录仍可能漏检。规则目标、配置列表和技能部署目标共用检测结果，未检测到的历史部署会标注并保留，不随其他 Agent 的更新被改动。主导航为项目、会话、Agent、清理；旧的规则／配置页签偏好及顺序自动迁移。小窗口直接提供「规则／配置」两项切换，首次进入默认规则，之后记住小窗口自己的页签。规则正文默认收起，点击规则集右侧箭头后展开，保存草稿、预览和应用固定在底部；配置直接展示最近使用的具体 Agent，支持选择预设、修改服务商和模型，放弃／保存同样固定在底部。技能通过右侧明确入口打开管理窗口，顶部展开按钮定位当前规则或配置；大小窗口共用草稿，但分别记住页签。配置有未保存修改时，切换 Agent 会先处理保存／放弃／取消；规则批量应用只包含当前显示的目标。

**技能（Agent → Skills）**
技能库由 Muster 独立管理，不依赖 Magpie。首页使用全宽列表，切换「技能库」与「本机发现」，搜索当前列表；技能库按来源分组并可折叠。技能行展示名称、单行简介和行内 Agent 启停。「本机发现」也提供相同的 Logo 操作：彩色表示根据当前本地目录可发现此技能，灰色表示尚未启用、无法读取或暂不支持，不代表正在运行的 Agent 已重新加载。

技能采用单源模式：每个库条目有一个固定的源地址，所有新 Agent 部署都是指向该地址的符号链接。本机导入沿用原源目录（或其稳定的源链接）；Git 导入及新建技能使用 `library/sources/<技能 ID>/<名称>/`。版本快照仍保存在 `library/skills/`，仅用于备份与回滚，不再是 Agent 的日常读取位置。

发现项按名称和内容指纹合并展示，同名不同内容仍分开。点击未启用的 Agent，会登记来源并创建链接，不再要求先手动导入。同一个本机源目录或同一 Git 仓库/ref/子目录后续更新会复用原条目；不会仅凭名称把不同来源合并。源内容、附属文件更新后，各链接立即指向新磁盘内容，但 Agent 可能仍需重新加载。

尚未作为唯一源的本机独立目录，点击关闭会把原目录或链接原子移动到 `library/disabled/<操作 ID>/`，它仍在“本机发现”中显示；再次开启会原样还原。已经注册为唯一源的目录不会被移走或替换成自链接；只能撤销其他 Agent 的附加链接。原路径被占用、父目录链接改变或保留副本被修改时拒绝恢复。停用与还原带有持久化操作日志，应用中断后会核对两端状态恢复记录；跨文件系统的移动会失败并保留原件，不做危险的复制后删除。

Muster 自己创建且仍与部署记录一致的条目可以直接点击撤销，即使该目录被其他 Agent 共享读取，也不会被“共享来源不可单独关闭”规则拦住。撤销只处理该 Agent 对应的托管部署，保留原始来源；依赖该部署的共享读取者会同步刷新。如果撤销后仍有其他来源可读，图标保持亮色并明确提示。

非 Muster 托管的共享来源、多来源同时可见，或原目录被其他 Agent 的链接引用时，保持亮灯；点击图标会就地展示不能单独关闭的原因、来源路径和读取它的 Agent，并提供 Finder 定位，不再直接禁用按钮造成点击无反馈。不会通过删除外部共享目录伪装单 Agent 停用。查看与停用均以本地文件和已适配的加载目录为依据，Agent 自定义禁用规则或运行时重载不在此次判断范围内。

点击技能名称打开详情，默认阅读 Markdown；顶部文件选择器可查看 `SKILL.md` 或附属文本文件。来源和版本默认折叠，点击「编辑」后再修改正文和附属文件。未保存草稿关闭前可保存、放弃或取消，保存草稿与发布版本仍是不同操作。

可登记本地文件夹或 Agent 现有目录为源，也可新建、搜索和编辑。编辑器分两部分：`SKILL.md` 正文，以及其余文本文件（`references/`、`scripts/` 等）；文本文件可直接修改、新增或移除，二进制资源只列出并保留原样、需在访达中编辑。附属脚本、参考资料和资源文件一起保存，原目录保留；扫描不会执行技能中的脚本。非法 YAML、重复元数据键、越界链接和特殊文件会显示问题，不能直接导入。

远程查找支持公开 HTTPS Git 仓库和 GitHub `owner/repo`，分支／标签和仓库内子目录分别填写，找到多个 Skill 后可勾选导入。需要本机可用的 Git；当前不提供 SSH、私有仓库认证或 GitHub tree 链接解析。网络操作可取消，每条 Git 命令最多运行 90 秒，暂存内容限制为 128 MiB；单个技能最多 2,000 个文件条目、32 MiB。

编辑器中 `⌘S` 只保存草稿；点击「应用到源」才修改唯一源，所有已连接的 Agent 共用新内容。源文件在编辑期间被其他程序修改时拒绝覆盖，需刷新后处理草稿；部署确认不会改变草稿的版本基线。发布、更新和回滚只替换技能内容，保留源目录中的 `.git`、`.DS_Store` 等扫描排除项，编辑器也不允许改写这些路径。列表每行的 Agent Logo 可直接启用或停用，悬停可查看目标目录；不再提供副本模式。技能库列表中的普通行内启停直接执行：目标已存在技能时自动备份后接管，不弹部署确认；停用时自动还原备份。批量部署及失效记录的重新接管仍使用预览。勾选技能时，列表底部显示批量部署面板，统一设置目标并预览。

目标位置已有同名技能目录时，行内启用会自动将原条目移入 `library/backups/<事务 ID>/` 再部署，底部显示备份结果，不需要再次确认。批量操作仍在预览中逐项确认接管（或用「全部备份并替换」）。停用该部署时，被移走的原目录或链接会还原回 Agent 目录。不含 `SKILL.md` 的目录永远不会被接管，规划与写入之间目标发生变化时会停止操作。

列表点击「选择」后显示复选框，不默认勾选正在阅读的技能。勾选一项或多项后，底部显示部署面板，统一设置目标并预览；再次点击复选框可全部取消，点「完成」退出选择模式。每行右侧展示设置中勾选的全部 Agent Logo，不再显示名称、勾号或链接标记；已部署显示原色，未部署置灰。名称、启停动作和共享目录说明通过悬浮提示展示；暂不支持部署或本机未检测到的目标不可点击。启停只控制对应部署，不会隐藏共享目录内容。

只有 Muster 自己创建且仍符合上次记录的内容可以直接替换或停用；预览后文件变化时停止写入。行内启停只检查并操作所点击的 Agent，不再因其他 Agent 的失效记录而阻断。刷新和每次操作会核对实际目录或链接，缺失、被接管或不可读的部署显示灰色。

点击失效部署会打开专用处理窗口：目标不存在时可「清除失效记录」，被外部工具接管时可「仅解除管理」，两者只移除 Muster 记录，不删除或恢复外部文件。处理前会再次核对目标及父目录，状态有变化则拒绝执行。也可选择「解除并预览重新部署」：先解除旧记录，再进入正常部署预览；已有技能必须确认备份接管，非技能目录不会被覆盖。取消第二步预览后，目录保持未托管状态。

解除管理会使涉及该路径的旧撤销事务失效；这些事务关联的原备份转为保留备份，不随普通 20 次历史轮换清理。重新部署的备份和撤销独立记录，之后停用或撤销会还原重新接管前的外部目录或链接。

一次正常部署包含多个技能或多个 Agent 时作为单个事务执行，失败会回退已完成步骤，中断记录会在下次加载时尝试恢复；外部改动会阻止自动回退。

「版本」菜单支持重命名、从技能库删除、检查更新、恢复历史内容。重命名修改源文件的 frontmatter；删除清理版本目录与草稿，但保留源目录。两者要求没有部署或待恢复的旧部署。恢复历史内容会更新唯一源，因此所有链接一起读取回滚内容。

本机源在外部更新时，刷新技能列表即可更新元数据，不再产生同一来源的新条目。Git 来源仍需「检查技能更新 → 更新源」获取远端内容；固定标签不会自动换到新标签。源缺失、损坏或目录父路径被改动时保留部署与快照，显示错误，不用旧版本静默替代源。

首次加载会对当前管理范围内的旧版部署进行兼容迁移：只重连仍与部署记录一致的链接或副本。失败项会在后续加载时重试，修复源后无需手动重置迁移记录；外部改动项仍保留并提示。原本机源仍可用且未被 Muster 接管时继续沿用；旧源已被接管或丢失时，在 Muster 的固定源目录中保留当前已收录内容，原备份不删除。冲突条目保留并标注“需要重新连接”。迁移前清单保存在 `library/migration-backups/`，技能版本快照继续保留。库格式升级为 schema 2，旧版应用会拒绝读取，不能直接降级覆盖。

技能部署支持 Claude Code（`~/.claude/skills`，支持 `CLAUDE_CONFIG_DIR`）、Codex（`~/.agents/skills`）、Pi（`~/.pi/agent/skills`，支持 `PI_CODING_AGENT_DIR`）、DeepSeek Harness（`~/.dsh/skills`，支持 `DSH_HOME`）、Hermes（`~/.hermes/skills`，支持 `HERMES_HOME`）以及 Cursor（`~/.cursor/skills`）。DeepSeek 的共享发现目录为 `$DSH_AGENTS_HOME/skills`，默认 `~/.agents/skills`；Cursor 还发现 `~/.agents/skills`、`~/.claude/skills` 和 `~/.codex/skills`。DeepSeek 与 Hermes 路径依据本机安装的加载器，Cursor 路径依据[官方技能说明](https://cursor.com/docs/context/skills)。自定义运行配置若禁用默认加载目录，需在对应 Agent 中启用；Muster 不改动运行配置。

Codex 的旧 `CODEX_HOME/skills` 只作为发现位置。共享目录可能被多个 Agent 读取，界面会说明影响范围；专属目录开关不能隐藏共享目录内的技能。部署完成不代表运行中的会话已经加载，未出现时需重新加载或新开会话。

当没有任何 Agent 既已安装又已纳入管理时，部署区会写明支持哪几个 Agent，并指出去「设置 → Agent 管理」启用哪一个，而不是只显示一句「暂不支持」。所有耗时操作（Git 克隆、扫描、导入、部署）都会在底部显示进行中的步骤和「取消」按钮，期间不再静默丢弃点击。

工具栏的「更多操作」菜单可恢复最近一次部署，最多保留 20 次部署操作；日志超出保留范围时对应备份目录一并清理（按事务 ID 匹配，`/var` 这类符号链接路径不受影响）。索引、部署记录和恢复日志保存在 `~/Library/Application Support/Muster/library/skills.json`；技能版本在 `library/skills/`，草稿在 `library/drafts/`，接管备份在 `library/backups/`。源目录的更新直接供符号链接读取；应用内草稿尚未应用、远端 Git 尚未拉取或 Agent 尚未重新加载时，不等于运行会话已经使用新内容。

当前未包含 Skill 路由、项目级部署、技能市场和 Magpie 专用迁移。YAML 使用固定的 Yams 6.2.2 源码（`Vendor/Yams`），许可证同时保留在源码及应用资源中，构建无需在线下载解析器。

**规则（Agent → Rules）**
把一份共享规则写进 6 个 agent 的用户级 md（只列用户级，仓库里的 `AGENTS.md` 不在范围内）：

| agent | 写入文件（按优先级） |
|---|---|
| Claude Code | `~/.claude/CLAUDE.md` → `AGENTS.md` |
| Codex | `~/.codex/AGENTS.override.md` → `AGENTS.md` |
| Pi | `~/.pi/agent/AGENTS.override.md` → `AGENTS.md` → `CLAUDE.md` |
| DeepSeek Harness | `~/.dsh/AGENTS.md` |
| Gemini CLI | `~/.gemini/GEMINI.md` |
| Cursor | `~/.cursorrules` |

目录可用 `CLAUDE_CONFIG_DIR` / `CODEX_HOME` / `PI_CODING_AGENT_DIR` / `DSH_HOME` 覆盖。`AGENTS.override.md` 存在时优先写它——写进 `AGENTS.md` 会被它盖住。

只替换 `<!-- muster:begin · written by Muster from its shared instructions -->` 到 `<!-- muster:end -->` 之间的块，文件里原有的内容一行不动；写之前看 diff，写完留备份，可以随时还原。

面板里每套规则是一行可折叠条目，小窗口默认收起正文及摘要；点击名称只选择规则集，点击右侧展开按钮才显示正文。展开只切换查看的草稿，编辑后自动保存到本地，也可按 `⌘S` 保存；名字可行内修改。查看、保存草稿和调整 Agent 开关都不会立即写入 Agent 文件。

查看「预览改动」后，可逐项或批量「应用改动」。关闭目标开关会预览移除该文件中的 Muster 共享块，点击应用后才执行。预览后若文件被其他程序修改，会拒绝覆盖并刷新预览，需要重新检查后再应用。

**配置（Agent → Configuration）**
配置列表来自设置中的管理清单。选择具体 Agent 后展示已有配置或缺失说明，可通过「全部配置」返回列表。页面顶部是配置文件卡片：路径、大小、修改时间，以及打开文件和 Finder 定位入口。Codex、Pi 可编辑用户级默认服务商和模型 ID：有本地模型列表时用下拉选，手填收在下拉底部的「自定义…」里，没有列表时直接是两个输入框；Claude Code、Hermes、Cursor、Warp、Magpie 只提供打开文件入口。Codex、Pi、Claude Code、Hermes 的配置目录分别遵循 `CODEX_HOME`、`PI_CODING_AGENT_DIR`、`CLAUDE_CONFIG_DIR`、`HERMES_HOME`。

改动会在页内实时以 diff 展示（键名取文件里的真实键），点一次保存即可；只替换目标字段，保留其他内容、格式和注释。底栏有「放弃修改」和「恢复上次配置」。写入前在 `~/Library/Application Support/Muster/configuration-backups/` 保存一份私有备份；仅当前文件仍与上次写入一致时允许恢复。检测到文件被其他程序修改会停止保存，需重新读取。符号链接保留，写入其目标文件。

第一版不编辑认证信息、不查询远端模型，也不热切换正在运行的会话。项目配置、Profile 和启动参数仍可能覆盖用户级默认值。Codex 顶层多行 TOML 值暂不支持表单编辑，遇到此类写法请使用原文件入口；表内内容保持原样。

Codex、Pi 支持保存具名模型预设，每个 Agent 分开管理。预设只保存名称、服务商和模型 ID，存于 `~/Library/Application Support/Muster/configuration-presets.json`，文件权限为 `0600`。点击「使用预设」后先填入表单，检查 diff 并保存后才修改 Agent 配置；有未保存改动时不能切换预设。

**设置**
设置包含通用（开机启动、全局热键 `⌃⌥A`）、Agent 管理（全局范围）、通知（活动暂停提醒、飞书机器人 webhook 和测试）、界面（外观、语言、舒适布局、tab 顺序）、环境诊断和关于。

「设置 → 界面 → 外观」提供跟随系统、浅色、深色三个选项，默认跟随系统。选择后立即应用到快速面板、管理窗口和原生控件，重启后保留选择；跟随系统时会随 macOS 外观变化自动切换。

管理窗口的标题栏与页面内容分离，页面滚动区域统一裁剪在标题栏和页脚之间，项目、会话、Agent 与设置页的长内容不会覆盖搜索或窗口按钮。

管理窗口的侧栏采用图标导航，设置固定在左下角。右侧连续展示常规、通知、界面、环境诊断和关于，点击左侧分区会滚动到对应标题，手动滚动时同步高亮当前分区；窗口内 `⌘,` 打开或收起设置，`⌘1`–`⌘4` 按自定义顺序切换主菜单。设置统一在管理窗口编辑：快速面板的齿轮和 `⌘,` 会收起面板、打开管理窗口并选中设置，保留上次的设置分区；右键菜单的「检查更新」会直接定位到「关于」。

「检查环境」会查看各 Agent 的命令行工具位置、配置与规则文件状态，以及 Muster 支持的功能。检查只读本地文件，不启动 Agent 或联系模型服务；Codex、Pi 的配置会通过现有解析器检查。其他配置只检查是否可读，不代表内容有效。自定义 Shell 路径可能与应用不同，因此「未找到」不等于未安装。

检查更新的结果直接显示在设置页。1.1.1 起的正式构建内置固定发布公钥，可下载带签名的 DMG，显示下载进度和已接收大小，支持取消下载。安装前用内置公钥验证 Ed25519 签名，再检查代码签名、应用标识、版本和 CPU 架构，之后才替换应用并重启。无公钥的旧构建需要手动安装一次 1.1.1 或更新的正式版；远端缺少匹配签名时也仅提供发布页入口。下载上限为 256 MiB；进入校验和安装阶段后不再提供取消。

中英文两套文案，跟随系统语言，也可在设置里指定。舒适布局会放大文字和行高；选择菜单与开关使用原生控件，支持标准键盘导航。管理窗口提供侧栏导航和更大的规则编辑区，较长的规则预览可展开查看全部行。

按钮提供悬停渐亮和轻微按压回弹，侧栏与分段选择的选中背景平滑移动。刷新、导入和检查更新时图标随任务状态旋转，规则草稿与配置保存后显示对勾。「设置 → 界面 → 减弱动态效果」提供跟随系统、开启、关闭三个选项，默认跟随 macOS 设置，选择后立即生效并保留到下次启动。开启后停用位移、缩放与旋转，Logo 停止播放，忙碌状态改用静态沙漏显示。

## 工作原理

- 会话：每 15 秒读取本机进程和 Claude Code、Codex、Pi 的 transcript 头尾元数据，不保存对话正文。
- 受保护目录：会话落在文档、桌面、下载、iCloud 云盘或外接卷里时，跳过 git 分支读取和 worktree 扫描，避免首次打开被系统授权弹窗打断；这些目录里的项目不显示分支，也不会被清理页扫描。
- 清理：基于进程和工作树信息生成清理计划，确认后执行。
- 规则与配置：写入目标文件前保留备份，数据存于 `~/Library/Application Support/Muster/`。
- Agent 路径、可执行文件名和支持能力统一定义在 `AgentRegistry`，供会话扫描、规则同步、技能、配置和环境诊断复用。
- 应用不运行审批 socket、不拦截 Agent 工具调用，也不请求审批通知权限。

## 已知限制

- 默认本地构建没有 Developer ID 或公证，首次打开可能需要手动放行，更新后登录项和系统权限可能需要重新授权。
- 更新不支持断点续传；构建只包含当前机器的架构，发布时需使用兼容目标设备的包，架构不兼容会拒绝替换。
- 只有 Claude Code、Codex、Pi 有 transcript 扫描，能区分运行与空闲、能复制 resume 命令；其余四个 agent 显示「活动未知」。同目录多候选的会话可能保留独立的进程与 transcript 条目。
- Codex 的本地模型下拉只在服务商为 openai 时读取缓存目录，使用自定义目录（`model_catalog_json`）的配置暂时要手填。
- 飞书 webhook 明文存在偏好设置里，且不支持机器人的「签名校验」。
- 仓库暂未声明许可证。
